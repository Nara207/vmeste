# Вместе — сервис совместного чтения (Laravel 10, PHP 8.1+)

Работает по-настоящему: регистрация и вход, библиотека, полка, комнаты по коду,
закладки, заметки, отметка «дочитал(а) до сюда», защита от спойлеров,
уведомления, профиль и админ-панель.
Дизайн — обычный CSS (`public/css/style.css`), без сборки через npm.

Проект сделан на Laravel 10, потому что на учебном хостинге веб-сервер работает на PHP 8.1.
Локально подойдёт любой PHP от 8.1 (проверено на 8.4).

## Запуск на своём компьютере

1. Нужны PHP 8.1+ и Composer. В папке проекта:

       composer install
       copy .env.example .env
       php artisan key:generate

2. В файле `.env` укажите базу данных (создайте пустую базу `vmeste` в MySQL):

       DB_HOST=127.0.0.1        (в OSPanel 6 — имя модуля, например MySQL-8.0)
       DB_DATABASE=vmeste
       DB_USERNAME=root
       DB_PASSWORD=

3. Создайте таблицы и демо-данные, запустите сайт:

       php artisan migrate:fresh
       php artisan db:seed
       php artisan serve

4. Откройте http://127.0.0.1:8000

Сбросить всё и начать заново: `php artisan migrate:fresh` и `php artisan db:seed`.

## Как проверить главное (защиту от спойлеров)

1. В обычном окне войдите как Анна, в приватном окне (или другом браузере) как Анара.
2. Анна: «Библиотека» → «Маяк на краю карты» → «Читать вместе». Скопируйте код комнаты.
3. Анара: «Мои комнаты» → «Присоединиться по коду» → вставить код.
4. Анара в главе 1 пишет заметки к последним абзацам (кнопка «Заметка»).
5. Анна открывает комнату: заметки Анары к абзацам, до которых она не дочитала, скрыты.
6. Анна нажимает «Дочитал(а) до сюда» у нижнего абзаца, и заметки открываются.
   Создатель комнаты может выключить защиту кнопкой справа.

## Как добавить книгу

Админ-панель → «Добавить книгу». Нужен txt-файл:
- главы начинаются со строки «Глава …» (например, «Глава 1. Тропа»);
- каждый абзац — с новой строки;
- кодировка UTF-8 или Windows-1251.

## Безопасность: что сделано и что проверить перед выкладкой на хостинг

**Уже сделано в коде**
- Роли: пользователь, администратор, главный администратор. Права на сервере проверяются при каждом действии.
- Назначать и снимать администраторов может только главный администратор и только после ввода своего пароля.
- Главного администратора нельзя удалить или лишить прав через сайт.
- Поля `is_admin` и `is_owner` нельзя выдать через формы: их нет в списке разрешённых для заполнения.
- Журнал (Админ → Журнал): кто, когда и кому выдал или снял права, кто удалил пользователя.
- Ограничение попыток входа: 5 неудачных в минуту для пары «email + адрес компьютера»; регистрация: 10 в минуту.
- Пароли хранятся в виде хеша; формы защищены токеном (CSRF); все данные проверяются.

**Первый главный администратор на хостинге** (демо-данные там запускать не нужно):

    php artisan user:admin почта@пример.ру --owner

Пользователь сначала регистрируется на сайте, потом выполняется команда.

**Чек-лист перед выкладкой**
1. НЕ выполнять `php artisan db:seed` на хостинге: там демо-аккаунты с паролем `password`.
2. В `.env` на хостинге: `APP_ENV=production` и `APP_DEBUG=false` (иначе страницы ошибок показывают внутренние данные).
3. Включить HTTPS и добавить в `.env`: `SESSION_SECURE_COOKIE=true`.
4. Задать новый `APP_KEY` командой `php artisan key:generate` и не публиковать файл `.env`.
5. Корневая папка сайта на хостинге должна быть `public` (чтобы папки `app`, `.env` и др. не были доступны из интернета).
6. Использовать длинный уникальный пароль главного администратора.
7. Выполнить `php artisan migrate --force`, затем `php artisan config:cache` и `php artisan route:cache`.
   (На учебном хостинге обычная команда `php` — это 8.1, то, что нужно проекту.)
8. Права на запись только у папок `storage`, `bootstrap/cache` и `public/covers`.
